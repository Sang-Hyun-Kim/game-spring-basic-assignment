# 0001. AI 에이전트 협업 구조를 AGENTS.md 단일 SSOT로 둔다

- **날짜**: 2026-09-08
- **상태**: 채택
- **결정자**: 저장소 소유자

## 배경

이 저장소는 **Claude Code**와 **Antigravity** 두 에이전트 툴로 동시에 작업한다.
두 툴은 각자 다른 규칙 파일과 MCP 설정 위치를 쓴다.

- Claude Code — `CLAUDE.md`, 프로젝트 `.mcp.json`, `.claude/skills/`
- Antigravity — 워크스페이스 rules, 사용자 전역 `mcp_config.json`

규칙을 툴마다 따로 적으면 **반드시 어긋난다.** 한쪽에서 고친 제약이 다른 쪽에 반영되지 않으면,
같은 저장소를 두 에이전트가 서로 다른 규칙으로 고치게 된다. 과제 제약(단방향 연관관계, 명세 일치 등)에서는
이 어긋남이 곧 오답이다.

또한 세션 사이에 맥락이 끊긴다. 툴을 바꾸는 순간 이전 세션의 판단·실패 기록이 전부 사라진다.

## 결정

1. **규칙은 `AGENTS.md` 한 파일.**
   `CLAUDE.md` 는 `@AGENTS.md` import 한 줄 + Claude 전용 항목만.
   `.antigravity/rules/00-agents.md` 는 "AGENTS.md 전문을 읽어라"는 포인터만.

2. **절차는 `.agents/playbooks/` 한 곳.**
   `.claude/skills/*/SKILL.md` 은 playbook을 가리키는 래퍼. 절차 본문을 복사하지 않는다.

3. **MCP 정의는 `.agents/mcp/servers.json` 한 곳.**
   `sync-mcp.mjs` 가 각 툴 위치로 배포한다. 각 툴의 설정 파일은 **생성물**로 취급한다.

4. **인수인계는 `.agents/handoff/CURRENT.md`.**
   모든 세션이 여기서 시작하고 여기서 끝난다. 툴 전환 지점이 가장 중요한 기록 시점이다.

5. **`.agents/` = 에이전트, `docs/` = 사람.** 폴더 하나로 독자를 구분한다.

## 근거

- 툴이 셋으로 늘어도 **포인터 파일 하나만** 추가하면 된다. 규칙 본문은 건드리지 않는다.
- `AGENTS.md` 는 특정 벤더의 포맷이 아니다. 툴이 바뀌어도 자산이 남는다.
- 실제 규칙을 한 곳에 모으면 "두 에이전트가 서로 다른 규칙을 본다"는 상태가 **구조적으로 불가능**해진다.

## 대가

- 규칙을 보려면 파일을 한 번 더 타고 들어가야 한다. 포인터 파일에 "요약본을 신뢰하지 마라"고 명시해 완화.
- 툴이 포인터/import를 무시하면 규칙이 적용되지 않는다. → 세션 초반에 에이전트가 `AGENTS.md` 를 실제로
  읽었는지 한 번 확인하고, 안 읽으면 포인터를 더 강하게 쓴다.
- Antigravity MCP 설정 경로가 미확인 추정값이다. → `.agents/mcp/README.md` 에 확인 절차를 남겼다.

## 대안으로 검토했던 것

- **툴마다 규칙 전문을 복사** — 초기에는 편하지만 어긋남이 시간문제라 기각.
- **MCP 설정을 각 툴에서 손으로 관리** — Antigravity 쪽이 사용자 전역이라 저장소로 공유 자체가 불가능. 기각.
